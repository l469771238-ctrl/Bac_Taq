# Z-Project Workplace

تطبيق إدارة فصل — **مس أسماء** هي المركز.

## الفكرة

الطالب بيدخل بـ**كود** من كشف الأسماء، بيعمل طلب انضمام، والمش بترفض أو تقبل.
القبول مش بيتم غير لما تحطه في **فصل → مجموعة**. 

## المراحل

| # | المحتوى | الحالة |
|---|---|---|
| ١ | الأساس: الدخول · طلب انضمام · لوحة المس · التنظيم · الإشعارات · التواصل | ✅ |
| ٢ | مساحة الملفات: رفع · تحميل · مجلد لكل عضو · درايف | ⏳ |
| ٣ | الأندرويد APK + النشر | ⏳ |

## التشغيل

```bash
cd zworkplace
node server/index.js          # http://0.0.0.0:3100
```

- **المس:** زرار «أنا مس أسماء» → كلمة المرور `asmaa2026` (تتغير بالكود أو `ZTEACHER_PASS`)
- **كشف الأسماء:** 273 كود في `../data/students.csv`

## الاختبارات

```bash
NODE_PATH=../tests/node_modules node tests/ui.test.js
```

## قاعدة البيانات

`node:sqlite` — الملف في `data/zwork.db`، وتقدر تغيّره بـ`ZDB=/path/to.db`.

| الجدول | إيه ده |
|---|---|
| `roster` | كشف الأسماء (كود + اسم ثلاثي) |
| `students` | الطلبة اللي طلبوا انضمام |
| `classes` · `groups` | الفصول والمجموعات (ولاد/بنات) |
| `messages` | إعلانات + دردشة |
| `sessions` | الجلسات (٦٠ يوم) |

## الشاشات

**الطالب:** طلب انضمام → كود → اسمه يظهر → باسورد → انتظار → دخول
**المس:** ٤ أزرار — التنظيم · الإشعارات · التواصل · الملفات

## الحفظ الخارجي — الأهم

كل استضافة مجانية بتدي قرص مؤقت. يعني السيرفر لو نام أو أعاد التشغيل،
القاعدة بتضيع — وده معناه إن الطالب يدخل ما يلاقيش حسابه.

**الحل:** القاعدة بتتحفظ في التخزين الخارجي كل ٥ ثواني، وأول ما السيرفر
يقوم بينزّل آخر نسخة **قبل** ما يفتح الباب لأي حد.

اختبرناه: سيرفر جديد تمامًا + قرص فاضي → الفصل والمجموعة والطلاب رجعوا كاملين.

### الملفات اللي بتتحفظ
- كل حاجة في القاعدة: طلاب · فصول · مجموعات · مطلوبات · دردشة · إعدادات
- ملفات الطلبة نفسها: في التخزين من الأول

### إعدادات
| المتغير | الافتراضي | إيه ده |
|---|---|---|
| `ZDB_KEY` | `db/zwork.db` | اسم الملف في التخزين |
| `ZSYNC_SEC` | `5` | كل قد إيه يتحفظ |

**ملاحظة:** الحفظ الخارجي بيشتغل مع `s3` و `drive` بس.
في وضع `local` (التطوير) مقفول عن قصد.
